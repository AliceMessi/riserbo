Riserbo — App map

Reference snapshot of the code after slice 5 (commit 5ecef2f). It can drift as the code changes.

What the app does

Riserbo hides personal data in a Swiss or Italian document before it is shared with an outside AI, then puts the real values back into the AI's answer. It has three pieces: rules for identifiers with checksums, Apertus for names and context, and a placeholder pipeline that replaces each value with a token such as [PERSON_1] and restores it later.

One action: pressing Redact

Reference route (3 stops)

A route to read in your editor. It was not toured interactively.

  1. track_2b/src/riserbo/server.py, function redact. This is the entry point: it runs the rules, calls Apertus, merges the results and returns spans, redacted text and mapping.
  2. track_2b/src/riserbo/llm.py, functions find_entities, _call, locate. Each chunk goes through the IDENTITY and CONTEXT passes with a JSON schema. locate keeps a span only if it is found verbatim in the document.
  3. track_2b/src/riserbo/pipeline.py, functions merge and redact. Checksum rules win overlaps. The same value always gets the same placeholder, and people are numbered in reading order.

To change this, start here

  • Add a new identifier (e.g. Swiss licence plates): add a regex and validator in detectors.py → find_all, plus a placeholder family in pipeline.py → FAMILY, plus a test in tests/test_detectors.py.
  • Change what Apertus looks for: edit IDENTITY_PROMPT / CONTEXT_PROMPT and their few-shot examples in llm.py, then run make eval to see the effect on leak rate.
  • Change the page: track_2b/src/riserbo/static/index.html (colours are CSS variables at the top).
  • Point to another model server: set LLM_BASE_URL and LLM_NAME (see .env.example).

A practice to reuse

Measure before trusting the model. The spec recorded an open question: can a 4-bit 8B model find indirect identifiers? The first live runs looked promising but were unstable: the same chunk sometimes returned an empty list. Running each sample twice exposed this, and the fix (two focused passes, minItems: 1 with a NONE sentinel) was confirmed by identical repeated output. The evaluation (src/riserbo/eval/run.py, results in data/eval/results.json) then put a number on it: 56.7% quasi-identifier recall. On any LLM feature, repeat the same input, and build a small scored test set before polishing the UI.

Run it again

Docker (no GPU needed)

cd track_2b && make run, then open http://localhost:8080.

Against an existing OpenAI-compatible endpoint

LLM_BASE_URL=http://host.docker.internal:1234/v1 make run-app

Tests and evaluation

make test and make eval
